1. Git vs GitHub

Git

A free, open-source version control system. It tracks changes to files and stores project history as commits.

Works locally on your computer. Basic Git operations do not require internet access.

GitHub

An online platform for hosting Git repositories, sharing projects, reviewing code, and collaborating with others.

Alternatives include GitLab and Bitbucket.

Remember: Git is the tool that tracks versions. GitHub is one place to host and collaborate on Git repositories.

2. The everyday workflow

1

Work

Edit or create files in your project folder. This is the working directory.

2

Stage

Choose which changes should go into the next commit using git add.

3

Commit

Save a snapshot in local history using git commit. Add a clear message.

4

Sync

Use git push to send commits to the remote repository, or git pull to bring remote changes into your current branch.

Working directory  →  Staging area  →  Local repository  →  Remote (e.g. GitHub)
       edit                 add              commit                  push

A typical loop: check status → stage changes → commit → push when ready.

3. Essential Git commands

CommandWhat it does
git --versionChecks whether Git is installed and available.
git config --global user.name "Your Name"Sets the author name recorded in your commits.
git config --global user.email "you@example.com"Sets the author email recorded in your commits.
git initStarts a new Git repository in the current folder.
git clone URLCopies an existing remote repository to your computer.
git statusShows changed, staged, and untracked files.
git add filenameStages one file. Use git add . to stage changes under the current directory—review status first.
git commit -m "Describe change"Records staged changes in local history.
git log --onelineShows a compact commit history.
git branchLists local branches.
git switch -c feature-nameCreates and switches to a new branch.
git switch mainSwitches to the main branch (if it is named main).
git pullFetches remote changes and integrates them into the current branch.
git pushSends local commits to the configured remote branch.

Starting a new local project

git init
git status
git add .
git commit -m "Initial commit"

Cloning an existing GitHub project

git clone https://github.com/OWNER/REPOSITORY.git
cd REPOSITORY

Replace the example URL with the repository's actual URL. Pushing to GitHub may require authentication and write permission.

4. Key terms in plain English

Repository (repo)

The project files plus the history Git tracks.

Commit

A saved snapshot of staged changes, with a message and author details.

Branch

A separate line of development, useful for features and experiments.

Merge

Combines changes from one branch into another; conflicts sometimes need manual resolution.

Remote

A named reference to another repository, often hosted online. origin is a common default name.

Clone

Creates a local copy of a repository, including its Git history.

Fork

A server-side copy of a repository on GitHub, often used to contribute to projects you don't own.

Pull request (PR)

A request to review and merge proposed changes into another branch or repository.

Conflict

Happens when Git cannot automatically reconcile overlapping changes. A person must resolve it.

5. Branches and collaboration

Example: add a login page without changing the stable version immediately.

git switch -c add-login
# Make and test your changes
git add .
git commit -m "Add login page"
git push -u origin add-login

On GitHub, open a pull request from add-login into the target branch. Teammates can review the code and discuss changes before it is merged.

If you don't own the original repository, a common open-source flow is: fork → clone your fork → make a branch → commit → push → open a pull request.

7. TortoiseGit: quick visual workflow

Commit your changes

  1. Open the project folder in File Explorer.
  2. Right-click the folder or relevant files.
  3. Choose Git Commit.
  4. Select the files to include.
  5. Write a useful message, such as “Fix navbar spacing”.
  6. Commit, then push if you want to upload the commit.

Get or send changes

  • Clone: create a local copy of a remote repository.
  • Pull: bring remote changes into your current branch.
  • Push: upload your local commits.
  • Switch/Checkout: move to another branch or revision.
  • Show log: inspect commit history.

Menu wording can vary slightly by version and repository state. Some actions need a configured remote or GitHub authentication.

8. Good habits and common mistakes

Do

  • Commit small, meaningful changes.
  • Write messages that explain the change: "Add input validation".
  • Run git status before committing.
  • Pull/review teammates' changes regularly.
  • Use branches for features and experiments.
  • Add a .gitignore for generated files and local secrets.

Avoid

  • Never commit passwords, API keys, tokens, or private credentials.
  • Don't assume a commit is uploaded to GitHub; push is a separate step.
  • Don't blindly overwrite or force-push shared history.
  • Don't commit build output, dependencies, or large files unless the project needs them.
  • Don't panic at a merge conflict—read the conflicting sections and resolve them carefully.

9. The 30-second recap

Git tracks project history. GitHub hosts repositories and enables collaboration.

add stages → commit saves locally → push uploads → pull integrates remote changes.

Branches isolate work; pull requests enable review; TortoiseGit gives Windows users a graphical way to do many Git operations.
